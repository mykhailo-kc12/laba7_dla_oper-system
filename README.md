# Лабораторна робота №7

## Відображення у пам’ять: `mmap`, файлові блокування та міжпроцесна взаємодія.

---

## Опис проєкту

Цей проєкт виконано в межах лабораторної роботи №7, присвяченої роботі з механізмом відображення пам’яті `mmap`, міжпроцесною взаємодією та файловими блокуваннями в середовищі Linux.

У роботі реалізовано два окремі програмні рішення:

1. **Завдання №1** — обмін повідомленнями між дочірніми та батьківським процесом через анонімний `mmap`.
2. **Завдання №2** — обмін повідомленнями фіксованого розміру через файловий `mmap`.

Для синхронізації доступу до спільних ресурсів використовуються:

- `fcntl.flock()` — у першому завданні;
- `fcntl.lockf()` — у другому завданні.

Для передачі Python-об’єктів через пам’ять використовується бінарна серіалізація за допомогою модуля `pickle`.

Додатково в проєкті реалізовано автоматичні тести за допомогою `pytest` та перевірку стилю коду через `flake8`.

## Мета роботи

Мета лабораторної роботи — дослідити використання спільної пам’яті для організації взаємодії між процесами.

- робота з `fcntl.flock()`;

- бінарна серіалізація через `pickle`;

## Опис основних файлів

### `src/task1_anonymous_mmap.py`

Файл містить реалізацію першого завдання лабораторної роботи.

У цьому завданні батьківський процес створює анонімну область пам’яті `mmap`, яка використовується для передачі повідомлень від дочірніх процесів до батьківського.

Дочірні процеси записують повідомлення у спільну область пам’яті. Щоб кілька процесів не записували дані одночасно в одне й те саме місце, використовується окремий lock-файл і механізм `fcntl.flock()`.

Основні особливості реалізації:

- створення анонімного `mmap`;
- створення тимчасового lock-файлу;
- створення дочірніх процесів через `os.fork()`;
- запис повідомлень у спільну пам’ять;
- синхронізація доступу через `fcntl.flock()`;
- збереження службового значення `used_size` на початку `mmap`;
- серіалізація повідомлень через `pickle`;
- читання всіх повідомлень батьківським процесом після завершення дочірніх процесів.

Формат повідомлення:

```python
{
    "pid": 1234,
    "str": "random message"
}
```

### `src/task2_file_mmap.py`

Файл містить реалізацію другого завдання лабораторної роботи.

У цьому завданні батьківський процес створює файл фіксованого розміру та відображає його в пам’ять за допомогою `mmap`.

Кожен дочірній процес записує повідомлення у свою заздалегідь визначену область пам’яті, яка називається `slot`.

Для синхронізації використовується `fcntl.lockf()`. На відміну від першого завдання, тут блокується не весь файл, а тільки конкретна область, з якою працює процес.

Основні особливості реалізації:

- створення файлу фіксованого розміру;
- відображення файлу в пам’ять через `mmap`;
- поділ пам’яті на окремі області `slot`;
- запис повідомлень фіксованого розміру;
- блокування конкретної області файлу через `fcntl.lockf()`;
- періодичне читання всіх областей батьківським процесом;
- використання роздільного блокування під час читання;
- серіалізація та десеріалізація повідомлень через `pickle`.

Формат повідомлення:

```python
{
    "pid": 1234,
    "slot": 1,
    "str": "random message"
}
```

## Принцип роботи завдання №1

У першому завданні використовується анонімне відображення пам’яті:

```python
mmap.mmap(-1, MMAP_SIZE)
```

Таке відображення не прив’язане до конкретного файлу. Воно створюється в пам’яті процесу, а після `fork()` стає доступним і дочірнім процесам.

На початку `mmap` зберігається службове значення `used_size`.

Це значення показує:

- скільки байт уже зайнято;
- з якого місця можна записувати наступне повідомлення;
- де закінчується область корисних даних.

Загальна схема пам’яті:

```text
[8 байт: used_size][повідомлення 1][повідомлення 2][повідомлення 3]...
```

Кожне повідомлення має власний розмір, який записується перед самим повідомленням:

```text
[8 байт: розмір повідомлення][pickle-дані]
```

Перед записом дочірній процес отримує ексклюзивне блокування:

```python
fcntl.flock(lock_file, fcntl.LOCK_EX)
```

Це потрібно для того, щоб кілька дочірніх процесів не змінювали `used_size` і не писали дані одночасно.

Після завершення запису блокування знімається:

```python
fcntl.flock(lock_file, fcntl.LOCK_UN)
```

Після завершення всіх дочірніх процесів батьківський процес читає всі повідомлення зі спільної пам’яті та виводить їх у термінал.

## Принцип роботи завдання №2

У другому завданні використовується файл фіксованого розміру.

Батьківський процес створює файл і задає йому потрібний розмір:

```text
file_size = children_count * SLOT_SIZE
```

Після цього файл відображається в пам’ять через `mmap`.

Кожен дочірній процес має власну область пам’яті — `slot`.

Наприклад, якщо `SLOT_SIZE = 512`, то області розміщуються так:

```text
slot 0: байти 0-511
slot 1: байти 512-1023
slot 2: байти 1024-1535
slot 3: байти 1536-2047
```

Кожен дочірній процес записує повідомлення тільки у свій `slot`.

Формат одного `slot`:

```text
[1 байт: статус][8 байт: розмір повідомлення][pickle-дані][нулі]
```

Статус показує, чи готове повідомлення:

```text
0 — повідомлення ще немає
1 — повідомлення готове для читання
```

Перед записом дочірній процес блокує свою область файлу:

```python
fcntl.lockf(file_obj, fcntl.LOCK_EX, SLOT_SIZE, offset)
```

Батьківський процес періодично читає всі області пам’яті. Для читання використовується роздільне блокування:

```python
fcntl.lockf(file_obj, fcntl.LOCK_SH, SLOT_SIZE, offset)
```

Такий підхід дозволяє безпечно працювати з різними частинами одного mmap-файлу.

Тести не запускають повну складну багатопроцесну логіку через `fork()` у кожному випадку, оскільки такі тести можуть бути нестабільними. Замість цього перевіряються основні частини програми:

- створення повідомлень;

- пакування розміру;
- розпакування розміру;
- запис службових даних;
- читання службових даних;
- формування записів;
- робота з `slot`;
- створення mmap-файлу;

Такий підхід дозволяє перевірити основну логіку програми без зайвої нестабільності.
